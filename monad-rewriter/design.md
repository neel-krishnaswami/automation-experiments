# Monadic rewriter design document

I want a small web app to rewrite terms with two monads, to generate
equational proofs. I describe the syntax of the language below, and
then describe the interface to the webapp.

The webapp should be implemented as a single-page Javascript app. 

# The Language

Propositional letters p are generated by the regular expression "[A-Z][a-zA-Z_0-9]*"
Constant names c are generated by the regular expression "[A-Z][a-zA-Z_0-9]*"
Variable names x are generated by the regular expression "[a-z][a-zA-Z_0-9]*"

The keywords do1, do2, let, lift, return1, return2, M1, and M2 are reserved
and may not be used as constant or variable names.

Types are generated by the grammar 

    b ::= p | (A) 
    A ::= b | M1 b | M2 b 

A signature Σ is a list of constant names and types 

    Σ ::= · | Σ <newline> c : A

A context Γ is a list of variables and their types

    Γ ::= · | Γ, x:A 

Expressions are generated by the grammar: 

    s ::= x | c | return1 s | return2 s | (e)  // simple expressions
    e ::= s                                    // complex expressions
       | do1 x <- s; e
       | do2 x <- s; e 
       | let x = s; e'
       | lift s 

This is one AST type, with the split into simple and complex expressions used to 
help guide the parser design of the parser. 

The typing judgement is of the form Σ; Γ ⊢ e : A 

     x:A ∈ Γ
     —————————————
     Σ; Γ ⊢ x : A


     c:A ∈ Σ
     —————————————
     Σ; Γ ⊢ c : A
     
     
     Σ; Γ ⊢ e : A
     ————————————————————————
     Σ; Γ ⊢ return1 e : M1 A 
     
     
     Σ; Γ ⊢ e : M1 A    Σ; Γ, x:A ⊢ e' : M1 B
     ———————————————————————————————————————————
     Σ; Γ ⊢ do1 x <- e; e' : M1 B
     
     
     Σ; Γ ⊢ e : A
     ————————————————————————
     Σ; Γ ⊢ return2 e : M2 A 
     
     
     Σ; Γ ⊢ e : M2 A    Σ; Γ, x:A ⊢ e' : M2 B
     ———————————————————————————————————————————
     Σ; Γ ⊢ do2 x <- e; e' : M2 B
     
     
     Σ; Γ ⊢ e : M1 A 
     —————————————————————
     Σ; Γ ⊢ lift e : M2 A


     Σ; Γ ⊢ e : A    Σ; Γ, x:A ⊢ e' : B 
	 ———————————————————————————————————
	 Σ; Γ ⊢ let x = e; e' : B 


Well-typed terms satisfy the following 7 equations: 

    do1 x <- return1 e; e'          == [e/x]e' 
    do1 x <- e; return1 x           == e
    do1 x <- (do1 y <- e1; e2); e3  == do1 y <- e1; do1 x <- e2; e3 
    
    do2 x <- return2 e; e'          == [e/x]e' 
    do2 x <- e; return2 x           == e 
    do2 x <- (do2 y <- e1; e2); e3  == do2 y <- e1; do2 x <- e2; e3 
    
    do2 x <- lift (return1 e); e'   == [e/x]e' 

Note that substitution must be capture avoiding! I give the definition of
capture-avoiding substitution [e/x]e' below, letting fv(e) be the set of 
free variables of e. We write fresh(y, S) to return a variable with a suffix
added to it ensuring it does not occur in S. If y does not occur in S, then 
y itself is returned

    [e/x] y  = if x = y then e else y 
    [e/x] c  = c 
    [e/x] (lift e') = lift ([e/x]e')
    [e/x] (return1 e') = return1 ([e/x]e')
    [e/x] (return2 e') = return2 ([e/x]e')
    [e/x] (do1 y <- e1; e2) = 
        let y' = fresh(y, fv(e)) in 
        [e/x] (do1 y' <- e1; [y'/y]e2)
    [e/x] (do2 y <- e1; e2) = 
        let y' = fresh(y, fv(e)) in 
        [e/x] (do2 y' <- e1; [y'/y]e2)
    [e/x] (let y = e1; e2) = 
        let y' = fresh(y, fv(e)) in 
        [e/x] (let y' = e1; [y'/y]e2)


# The User Interface 

I want a user interface for deriving equations between terms. There should be 3 panels. 


In the first panel, the user should be able to write a signature as a list of newline-separated
constant names and types: 

      c1 : A1
      c2 : A2 
      ... 
      cn : An


In the second panel, the user should be able to input a term. The term should be typechecked, 
and ill-typed subterms should be highlighted in red, with an error message displayed as a 
bubble when the user hovers over it. Once any subterm of a term has an error, the term
itself should not display any errors – in other words, only the smallest wrong subterms
should be highlighted. So in an expression like: 


    do1 x <- <ERROR1>; 
    (do2 y <- <ERROR2>;
    return2 e)

Only the subterms corresponding to ERROR1 and ERROR2 should be highlighted, even though 
both the do1 and do2 sub-expressions can be considered ill-typed. 

Once the user has typed a well-typed term, the correct term should be printed in the
third panel. The third panel consists of a list of terms, initially consisting only 
of the user's original term. 

When the user highlights a subterm of the bottom term, this term should be matched
against the equations that well-typed terms satisfy. A list of the matching equation
instances, should be presented to the user. If they press the appropriate key, then 
the rewrite should be applied, and the term with the rewrite applied should be added
to the sequence of terms. 

For example, if the highlighted subterm is: 
 
    do1 x <- (do1 y <- e1; e2); return1 x 

Then the system should display the possible rewrites: 

    1. do1 y <- e1; e2
    2. do1 y <- e1; do1 x <- e2; return1 x 

The rewrite choices are listed in the following order: first the left-to-right
reductions, then the deterministic right-to-left expansions (eta-expansion and
un-associativity), and finally an un-substitute option. Invoking un-substitute
lets the user select one or more occurrences of a subterm e inside the selected
term, and then choose which of the beta equations to apply right-to-left,
abstracting the chosen occurrences as a fresh do-bound variable.

The list of terms is an equational proof. There should also be a button to 
export this proof to a file. 
    
## Code formatting

The system should format code as follows: 

An expression do1 x <- e1; e2 should be laid out as 

  do1 x <- e1;
  e2

That is, a newline should follow each semicolon, and the indentation level of e2 should start
at the same column as the do1. do2 and let should be laid out similarly. 

If the expression e1 is a do1/do2/let expression, then it should increase the indentation 
level to where the do/let starts. That is, do1 x <- (do1 y <- e1; e2); e3 should be laid out as: 

  do1 x <- (do1 y <- e1;
            e2);
  e3
